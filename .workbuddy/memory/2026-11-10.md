# 2026-11-10

## MineCube 3D（Godot 3D 扫雷）原型

- 需求：2D 扫雷的三维化，每个格子是立方体，表面数字为三维邻域雷数。用户确认：26 邻域、实体外壳逐层剥离、默认 4×4×4（6 雷）、数字印在所有暴露面、本次走原型验证。
- 设计文档：`doc/design.md`。原型：`prototypes/minecube/`（Godot 4.7.2），报告 `prototypes/minecube/REPORT.md`，索引 `prototypes/index.md`。
- 关键设计：3³ 体心被完全包住、不可点击 → 已揭示方块保留网格与数字但移出拾取层（collision_layer = 0），射线穿过命中内层。视觉与拾取分离，是这套方案的支点。
- 关键教训：`(1−p)^邻接数` 估算三维 0 格比例在边界上失效。实测 4³/6 雷 0 格占 24.4%、首击平均展开 60.8%，比公式预测的 3.3% 高得多。三维扫雷的连锁展开是过强而非过弱，密度要往上调（4³ 配 9 雷 → 48.4%）。
- Godot 实现要点：Label3D 必须 `double_sided = false`，否则透过缝隙看到邻块镜像字形。中文 HUD 需读系统字体（macOS PingFang），Godot 内置字体无 CJK。
- 验证方式：`-s res://tests/logic_test.gd`（28 断言）、`balance_probe.gd`（平衡统计）、`capture.gd`（无头截图）。首次导入需 `--editor --quit` 才注册 class_name 全局类。

## 2026-11-11 插旗 / 立体雷 / 和弦

- 插旗改为沙色小方块（0.52）+ 顶面小旗（旗杆 0.30 + 橙色矩形旗面）。红色留给"踩雷"，避免误读。旗杆高度卡在方块顶面与上方方块底面之间 0.33 的空隙内。
- 立体雷用 Blender 5.3 生成：`assets/build_mine.py` → `assets/mine.glb`（球体 + 赤道箍 + 14 根锥刺，外径 0.80）。Blender 需 `-b --factory-startup -noaudio -P`，不加 `--factory-startup` 会被杀（退出码 137）。
- **金属度踩坑**：场景没有环境贴图，metallic 0.9 直接渲染成黑块。降到 0.45 才看得出球面。
- 和弦按微软扫雷规则实现：数字格上旗数 == 该数字时，揭开所有未插旗的相邻未揭示格；旗数不等无反应；旗插错会引爆。
- 碰撞层拆两套：`LAYER_SOLID`(1) 未揭示/已插旗、`LAYER_OPEN`(2) 数字格。揭示射线只认 1（可穿透数字格命中内层），和弦/插旗认 1|2。
- 游戏结束时已正确插旗的雷位保留旗面；插错的旗翻出底下数字。
- `min_value`/`index_of` 等返回 Variant 时 `:=` 推断会失败，测试里需显式写 `var x: int =`。

## 2026-11-11 圆角方块 / 问号标记 / 完成弹窗

- 方块最终定为**削角立方体**（`assets/build_cube.py` → `cube_rounded.glb`）：只对八个顶点做球形切削（沿棱 0.30、12 段），十二条棱保持直边不倒角。六个面完整平直，棱是直线，角是大圆弧。
- **关键着色处理**：把六个主面设为平直（按面法线是否为单位轴判断），否则平面上的大多边形会被平滑拉出斜纹。
- 放弃过的方案：①Bevel 两步倒角（角与棱抢同一条边长、且有斜纹）；②截面放样做圆角矩形（看着像软垫，棱变成过渡带）。**用户要的是"削掉的角"，不是"倒圆的棱"**。
- 视图按 0.88（隐藏）/ 0.70（已揭示与标记）缩放同一个共享网格；标签字号 36，角半径变大后 44 号会顶到圆角。
- **Blender 倒角有重叠钳制**：顶点倒角先吃掉边长，棱的倒角会被钳住，单独加大棱的数值几乎无效；关掉 `use_clamp_overlap` 会让网格膨胀到 1.99 倍。要更圆的棱只能先降顶点的值。
- 试过直接放样建"面先切 30% 角、再每边切 10%"的精确骰子形状（平面 0.8、角半径 0.2、棱 0.1），用户判定比修饰器版本差，已弃用。**用户偏好偏圆润的软骰子手感**，不再追求严格几何规格。
- 右键标记不再要求盘面已布雷：雷在首击后才放，标记记在格子上，首击前的旗会保留。`cycle_mark` 去掉 `not generated` 守卫，`_on_flag` 同理。
- 插旗改成"印在面上"：系统字体没有旗帜字形（U+2691/2690/1F6A9 在 PingFang 全无），改用运行时生成的 96×96 纹理（深杆 + 深边琥珀三角）贴 QuadMesh。面片按需创建，只有被标记的格子才有。
- 右键改为三态循环：未标记 → 旗 → 问号 → 未标记。只有旗计入 flag_count；问号不挡揭示，和弦会把它当未标记处理。
- 新增 `result_panel.gd`：清空后弹窗显示用时与盘面，可再来一局。胜利处理抽成 `_finish_win()`，避免两条路径（左键 / 和弦）各写一遍。
- 设置上限放开到 9 阶。9³ 全开实测 59.7 FPS、7362 节点（垂直同步封顶），无需 LOD。
- 踩坑：成员 `result` 被 `_on_reveal` 里的局部 `var result := logic.reveal()` 遮蔽，报 "open() not found in base Dictionary"。面板改名 `result_panel`。
- 相机取景系数从 extent×2.35 调到 ×2.7，否则 9 阶盘面会被画面下沿裁掉。

## 2026-11-11 每面计数 + 按面展开

- 每面只数该面所在平面内的 8 邻格（`BoardLogic.face_counts`，长度 格数×6，顺序 +Z -Z +X -X +Y -Y，必须与 `CellView._faces` 一致）。
- 覆盖关系：轴邻格被 4 个面统计、棱对角被 2 个、**体对角（8 个）不被任何面统计**。实测 5.86% 的非雷格是"26 计数>0 但六面全 0"，显示为空白但不消失的方块。
- 展开改为按面判定：某面为 0 就打开该平面 8 格并连锁。副作用是极其激进，4 阶点一次能开掉九成。
- 修了射线拾取的幽灵格问题：`new_game()` 用 `queue_free()`，同一帧里上一局的碰撞体还活着，点击会命中旧格。`_pick` 里加了 `cells[idx].body == collider` 校验。
- 和弦判据仍是 26 计数，和界面上显示的每面数字不是同一个量——已记录为待决策项。

## 2026-11-11 间距滑块（游戏内）

## 2026-11-11 间距 = 中心距（修正）

- 用户要的是**方块中心之间的距离**，不是方块大小。`AppSettings.spacing`（100–180%）现在换算成格距倍率 `pitch()`，方块位置 = 坐标 × pitch，尺寸保持 `hidden_size()=0.88` / `revealed_size()=0.70` 不变。
- 改间距走 `_relayout_cells()`：重算 origin 与每个方块的位置，再 `camera_rig.frame(size, pitch)` 重新取景。`_framed_pitch` 与 `_framed_side` 一起判断是否需要重新取景。
- 原 `const SPACING := 1.0` 已删除。

## 2026-11-11 中键平移 + 鼠标映射

- 相机加了 `pivot`（观察中心）与 `pan(relative)`：沿相机自身 right/up 平移，`_apply` 里 `look_at(pivot)`。`frame()` 会把 pivot 复位到原点。
- `AppSettings.mouse_map = [左, 中, 右]`，枚举 `MouseAction { NONE, REVEAL, FLAG, CHORD, PAN }`，默认 `[揭示, 平移, 插旗]`，存 `[input] left/middle/right`。
- 输入分派：按下时若左右键都是"点击类"（揭示/插旗/和弦）才置和弦；拖拽时若按住的键里有平移键就平移、否则旋转；松开时按该键的功能分派。
- 间距上限放到 200%，允许溢出画面（配合中键平移与滚轮观察）。

## 2026-11-11 代码审查

修掉的问题：
1. `game.gd` 里 `hud.spacing_changed.connect` 与 `hud.set_spacing` 各重复一次（批量替换的后遗症）——间距改动会触发两次重排。
2. `AppSettings.spacing` 从未落盘，每次启动都回到 100%。
3. 换局只在阶数变化时调 `frame()`，导致平移后的 pivot 残留；新增 `CameraRig.reset_view()` 并在 `new_game` 里调用。
4. 选项页打开时不停表，和「开局」页行为不一致。
5. `_face_mask` 不考虑间距：拉开后每个面都能从缝里看到，却仍按遮挡剔除。现在 pitch ≥ 1.15 直接返回 63，并在跨阈值时重刷全部格子（`_sync_open_view`）。
6. HUD 提示行写死键位，改了映射就显示错误信息。改成 `refresh_hint()` 按 `mouse_map` 生成。
7. 删掉死函数 `_refresh_all_cells`；修正 `PEEK_GAP` / `spacing` 的过期注释。

测试补充：间距落盘、间距 130% 时六面全可见、换局复位 pivot、浮层阻挡与 Esc 关闭顺序、随机盘面计数不变量。
